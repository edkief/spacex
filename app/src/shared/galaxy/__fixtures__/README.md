# Galaxy determinism fixtures

Committed snapshot fixtures that lock the determinism contract (SC-2). They
are **regression guards**: any generator change that alters them is a
breaking change to seeded content and must be deliberate.

## Files

- `snapshot-stars-dev-seed.json` — full star chart (dev seed `drift-dev-seed-001`, 200 stars)
- `snapshot-system-star0.json` — system of star #0
- `snapshot-system-star1.json` — system of star #1
- `snapshot-chunk-0-0.json`, `snapshot-chunk-1-0.json`, `snapshot-chunk-0-1.json` —
  chunks (0,0), (1,0), (0,1) of the first landable planet of star #0's system
- `stars-dev-seed.json`, `system-dev-seed-star0.json`, `surface-dev-seed-chunk00.json` —
  older golden fixtures from TASK-3/4/5 (embed samples + checksums)

Snapshot files are pretty-printed **canonical JSON** (sorted object keys) so
they are byte-stable across platforms for a given seed.

## Regenerating

Fixtures must **only** be regenerated by an explicit, deliberate command
after an approved generator change:

```sh
npm run snapshot:update   # rewrites the six snapshot-*.json files (runs prettier)
```

The test suite (`src/shared/galaxy/snapshots.test.ts`) only compares and
never writes. When regeneration is required:

1. Confirm the generator change was approved and the new output is intended.
2. Run `npm run snapshot:update` and review the fixture diff.
3. Commit the fixtures with a message noting the **breaking seed behavior**
   (existing generated content for the seed changes).

Do not regenerate opportunistically (e.g. to silence a test) — a drifting
fixture means the generator changed, which is the bug to investigate first.
