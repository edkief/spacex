## Dead ends
- **In-process test server has no chat routing**: first version of `chat.integration.test.ts` booted the server in-process like `lifecycle.test.ts` (buildServer + attachWebSocket without `onGameMessage`) — chat frames never reached the shard because the dispatch wiring lives in `server/index.ts`. Rewrote on `server-child.ts` `bootServer` (real process), which is what the crash-restart/shutdown tests use.
- **`WsTestClient.next()` returns the whole envelope, not the payload** — first integration version cast the envelope to `ChatMessage` and got `undefined` fields; must read `.payload`.
- **`join()` helpers that consume `enter_system`**: I consumed the join answer inside `join()`, then waited for `enter_system` again for the late-joiner → timeout. Capture the snapshot at join time.
- **Per-player home systems**: claiming a second player and using ITS `homeSystemId` put the late joiner in a DIFFERENT (empty) system → empty chat history. Pin one system id (module-level `SYSTEM_ID`) across the tests.
- **ANSI stripping regex order**: `C0class|CSI` fails because at an ESC byte the C0 alternative matches the lone ESC first, leaving `[31m` behind. CSI alternative must come FIRST: `/(\u001b\[[0-9;?]*[ -\/]*[@-~])|[C0/DEL/C1/format chars]/gu`.
- **Don't mix TASK-65 and TASK-16 limiter constants in tests**: `ratelimit.test.ts`'s `CHAT_WINDOW_MAX` import is 10 (TASK-65 default), not 5.
