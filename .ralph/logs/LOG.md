### 2026-10-21 — Iteration 5 (TASK-18) — 16-player load test over real WebSockets -> **DONE**
  - **Two real production bugs found by the load test and fixed.**
    1. **Production delivered ZERO `entity_update` frames.** `galaxy/router-load.ts` built every shard with `broadcast: () => undefined`, so the sim's 10 Hz snapshot went nowhere; only the on-demand frames (`enter_system`, spawn, disembark) reached sockets. Replaced with a real `SnapshotBroadcaster` that fans `{type:'entity_update', payload:{systemId, tick, entities, lastAppliedSeq}}` to every `shard.connections` key through the existing `connSender`. Snapshot rate 0.00 Hz -> 10.00 Hz.
    2. **The 10 Hz frame was 47.8 KB — 76 % of it static.** 120 deposits were re-serialized 10x/s for 33 KB of the 43 KB payload. Split the stream: `buildDynamicSnapshotEntities()` (the tick broadcast) omits the static kinds (`deposit`, `terminal`, exported via `isStaticEntityKind`), while `buildSnapshotEntities()` still returns everything for `enter_system` / `warp_arrived` / event paths. Deposit changes now ride a targeted one-entity frame: new `shard/deposit-update.ts` -> `pushDepositUpdate(shard, deposit)` pushes a single-entity `entity_update` to every connection within `DEPOSIT_UPDATE_RADIUS_M` (1.5 km) from the mining award path. Frame **47.8 KB -> 15.0 KB**, and RTT p95 fell **95.6 ms -> 93.3 ms** with a third of the wire traffic.
