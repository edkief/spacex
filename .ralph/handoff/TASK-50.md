## Dead ends
- **static `renderToStaticMarkup` can't drive the store subscriptions** — the components subscribe to the targeting store in `useEffect`; static markup renders the initial (empty) view → empty HTML. Fix: happy-dom + `createRoot` + `act` (`renderWithEffects` in the test file).
- **happy-dom does NOT normalize inline style hex→rgb and does truncate px to 6 decimals** (`left: 853.333333px` not `853.3333333333334px`) — don't string-compare style output against `styleFromRect`; parse `style.left` and use `toBeCloseTo`.
- **`vitest.config.ts` default env is `node`** — the test file needs the `// @vitest-environment happy-dom` pragma (happy-dom is already in node_modules).
- **`requestAnimationFrame` works in happy-dom** — plain `await new Promise(r => setTimeout(r, 50))` lets a tick run; no fake-raf polyfill needed.
- The projection "halving fov" / "aspect 2 doubles offset" intuition tests were wrong: with three.js-style horizontal-aspect scaling the pixel offset is `(x/depth)/tan(fov/2)/aspect × w/2` — rewriting with explicit tan math fixed it (the formula-based asserts in `projection.test.ts` are the right shape).
- threat ping store API: `ingestCombatEvent` needs a full `CombatEvent` (source `{kind:'player'|'ai', id}`, `weapon`, `damage`, `shieldHit`, `hullHit`) and resolves the attacker by **id OR callsign** — in tests, use real wall-clock `Date.now()` so the 3 s fade window is open when you render.
