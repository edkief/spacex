## Dead ends
- **The "server drops browser input frames in a two-connection setup" theory is FALSE.** The shard registers ONE connection per player: when the browser joins, its connection SUPERSEDES the raw WS observer (TASK-17 `registerConnection` evicts the stale conn; `broadcast()` only sends to registered conns) — the raw observer goes DEAF on supersede by design. The server was flying the ship the whole time. Observe server state via the browser's OWN inbound `entity_update` frames (the init-script WebSocket-subclass tap in `flight.spec.ts`), never via the raw observer. Do not chase server sim, `shard.enqueueInput` stale-seq, or `conn.lastSeq` sharing.
- **`page.evaluate(fn, argA, argB)` passes ONLY argA** to the in-page function — second+ args are silently dropped. Bundle all constants into ONE object arg. (Burned 3 debug rounds on flight.spec as `undefined.x`/NaN, and again this session as `ReferenceError: dockedBack is not defined`.)
- **`npx playwright test tests/e2e/...` without `--config playwright.e2e.config.ts` → "No tests found"** (the main `playwright.config.ts` ignores `tests/e2e/**`).
- **The deleted debug-entership spec is not a valid reproduction vehicle as written:** 4/4 of its runs failed at steps EARLIER than the real spec's flake point (stricter 12 s waits + a per-message `send` tap overhead).
