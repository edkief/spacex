## Next steps
1. **Fix the one known bug in `tests/abuse/property.spec.ts`:** the run sells ZERO units. Root cause (found by debug run): the test adds BOTH the ship and the character with `shard.addEntity`, and `addEntity` does `playerEntities.set(entity.playerId, entity)` — the character (same `playerId`) OVERWRITES the ship in `playerEntities`, so `handleSell` reads the character as "the ship" → `{ok:false, code:'unknown-ship'}` for every sell (and mining awards land in the character's inventory — the invariants already count that, so only the sells break). Production avoids this: `handleExitShip` creates the character via `this.entities.set(`char:${playerId}`, …)` (shard.ts ~line 1685), NOT `addEntity`. Fix: in the property spec, replace `shard.addEntity({...character...})` with `shard.entities.set(`char:${PLAYER_ID}`, {...})` (keep the ship on `addEntity`). Re-run: `cd app && npx vitest run tests/abuse/property.spec.ts` — expect green including `soldUnits > 0` (the stub repo makes sells succeed once the ship is findable; if `soldUnits` is still 0, inspect the `handleSell` result codes — `not-at-station` would mean the terminal-entity lookup changed).
