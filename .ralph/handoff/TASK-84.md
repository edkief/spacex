**Step 2 — pad flattening in ChunkBuild (GREEN):** `app/src/client/world/chunk-geometry.ts`. `ChunkBuild` constructor takes optional 4th arg `pad?: PadInfo`. New `blendedAt(gx, gz)` applies the SHARED `padSurfaceHeight(wx, wz, gridH, pad)` in WORLD coordinates, used for the near-LOD position fill AND the analytic normals (central differences over blendedAt — the ramp into the pad blends smoothly). The raw `grid` is untouched so the placement pass / biome / pad derivation stays bit-identical to the server (bit-identical tests in chunks.test.ts still pass). `padActive` gate: only chunks whose square's clamped-corner distance to the pad ≤ `PAD_FLAT_BLEND_OUTER_M` pay the blend (usually 1 chunk) — build cost stays flat elsewhere. `advanceFar` also uses blendedAt. ImpostorBuild unchanged (spec: pads are full-build terrain).

**Step 3 — planet-terrain module (GREEN):** `app/src/client/world/planet-terrain.ts` (new, <100 lines). `MOUNT_RANGE_M = PLANET_SURFACE_RADIUS_M + 2000` (4000), `MOUNT_RELEASE_RANGE_M = +500` (4500). `terrainPlanetFor(pos, system, current)`: current landable planet held within release band, else nearest landable within mount range (deterministic), gas giants/stale ids never mount. `chunkInSurface(chunkX, chunkZ, anchor)`: chunk's 320 m world square intersects the PLANET_SURFACE_RADIUS_M circle (clamped-point distance ≤ radius, boundary inclusive). Tests: `planet-terrain.test.ts` (new, 9 tests).

**Streamer options (GREEN):** `app/src/client/world/chunks.ts` — `StreamerOptions.pad` (passed through to every full `ChunkBuild`) and `StreamerOptions.chunkFilter?: (cx, cz) => boolean`. New describe in `chunks.test.ts` (2 tests): filter respected (cached/mounted/active all pass it), and `pad` option flattens the built chunk at the synthetic pad plane (12.5 m at pad center, 5 m out).
